While majority of Core Trust Seal (CTS) requirements depends solely on
settings and policies of a particular repository, there are several
requirements that discuss the underlaying technical infrastructure.

This document answers those questions based on [CTS requirements
2026--28](https://www.coretrustseal.org/why-certification/requirements/),
namely sections R14 to R16. For those, we provide commentary on internal
workings of the infrastructure and links to appropriate documentation.

Conventions: texts _in italics_ are expected to be discussed further based on a
particular repository implementation.

### Any checks (i.e. fixity checks) used to verify that a digital object has not been altered or corrupted from deposit to use.

Ceph provides two basic mechanisms to ensure data fixity: when data is
split to blocks and written to disks, each block is provided with a
checksum and the checksum is checked whenever the block is read and also
during periodic data checks (deep scrubbing). Should a block be damaged, it
is replaced with a block from another replica.

The other mechanism is ETags that provide checksums for objects and/or
their parts in case of multipart uploads.

_Finally, the repository software itself provides checksums._

## R16. The repository protects the facility and its data, metadata, products, services, and users.


### The levels of security required for different data and metadata and environments, and how these are supported.

Level of security is anually evaluated during ISO 27001 risk assesment
procedures.

### The IT security system, employees with roles related to security (e.g. security officers), and any risk analysis approach in use.

The fundamental security principles applied by CESNET to e-infrastructure
and services are described in the document
[https://www.cesnet.cz/en/cybersecurity](https://www.cesnet.cz/en/cybersecurity).
CESNET has implemented an Information Security Management System (ISMS) in
accordance with the ISO 27001 standard series; it has held certification
since 2018 and has appointed a Chief Information Security Officer (CISO).
CESNET operates a security CSIRT team (CESNET-CERTS,
[https://csirt.cesnet.cz](https://csirt.cesnet.cz)), which is part of the
TF-CSIRT platform of European security teams. CESNET operates a Security
Operations Center (SOC), maintaining a 24/7 monitoring center and a 24/7
Network Operations Center (NOC). It also runs an internal penetration
testing team as part of its forensic laboratory (FLAB,
[https://flab.cesnet.cz](https://flab.cesnet.cz)), which conducts regular
penetration testing of key components of the CESNET e-infrastructure,
including the NRP infrastructure and related services.

### Measures in place to protect the facility. How the premises where digital objects are held are secured.

Access to the CESNET headquarters and other CESNET work locations is
managed on a “need-to-know” basis, with a separate perimeter designated for
visitors. Security requirements for the operators of the data centers where
the technology is housed are defined in supplier contracts; in addition to
physical specifications (such as structural resilience), these contracts
also establish principles for access control and surveillance.

### Any security-specific standards the repository references or complies with.

ISO 27001, see [https://www.cesnet.cz/en/cybersecurity](https://www.cesnet.cz/en/cybersecurity) for details.

### Any authentication and authorization procedures employed to securely manage access to systems in use.

Access to operated systems is controlled using the [e-INFRA AAI](https://docs.account.e-infra.cz/en/docs/access/account). The AAI system will be rebranded CESiD during 2027.
