This section collects technical documentation for repositories in the National Repository Platform — the repository systems, the services the platform provides, supporting tools, how-tos and policies. It is a reference and a collection of links rather than a guide, written for repository administrators, operators of NRP services, and software developers.

> Questions, errors or missing pieces: [support@eosc.cz](mailto:support@eosc.cz). If you are an end-user of a repository, this section is not for you — we have [documentation for end-users](../end_users/end_users) as well.

## What is your part

What you arrange depends on how your repository uses the NRP, and so does where you start. The three situations are 4.1, 4.2 and 4.3 in the [**Conditions for Creating New and Modifying Existing Domain Repositories in the National Repository Platform**](./operating-repositories-in-the-nrp/conditions-for-creating-repositories), which is the binding text — the table below is a summary.

| Your situation | The NRP provides | You take care of | Start with |
| --- | --- | --- | --- |
| **Core implementation, highly customised (4.1)** | test and staging environments, production operation, notice of upcoming changes | your custom code in git, its compatibility and maintenance, and asking for releases | [**Repository Checklist**](./operating-repositories-in-the-nrp/repository-checklist) |
| **Your own repository system, joined to the NRP (4.2)** | shared services: AAI, metadata directory, NKR, identifiers | the system itself, its updates and compatibility, and the integration with the shared services | [**Conditions**](./operating-repositories-in-the-nrp/conditions-for-creating-repositories), then [**Shared Services**](./shared-services) |
| **NRP environment only (4.3)** | storage, Kubernetes, PostgreSQL | your application, its deployment, security baseline and monitoring | [**Conditions**](./operating-repositories-in-the-nrp/conditions-for-creating-repositories), then [**Shared Services**](./shared-services) |

The Repository Checklist is written for 4.1. For 4.2 and 4.3, additional steps apply and they are set out in the Conditions.

## Community and materials

- [**RepoBuilders Community**](./community/repobuilders) — an informal channel for sharing experience, with meeting notes, templates and methodologies. **For a question that needs an answer, use User Support.** Join on [Discord](https://discord.gg/24CTJayZYD).

- [**FAQs**](./faq) — answers that do not belong to any single page yet: Ceph/S3 and pre-signed URLs, how granular datasets should be, what a repository needs to assign DOIs.

- [**How to Contribute to This Documentation**](./documentation-contribution) — where the source lives, and how to report a correction or open a pull request.
