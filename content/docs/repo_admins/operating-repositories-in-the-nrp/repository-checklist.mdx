This page lists what the user group establishing a repository needs to do. It is not a replacement for the conditions or the consultations — it is the list of steps, with the document or the form for each one.

> **Scope.** This checklist is written for a repository on a **core system** — use case 4.1. For the other ways of joining the NRP environment — your own system on NRP resources (4.2) and an existing repository, integrated (4.3) — additional steps are likely to apply. They are set out in the **Conditions for Creating New and Modifying Existing Domain Repositories in the National Repository Platform** — see row 1.1.

Two checklists apply to a repository in the NRP:

- **Establishment** — from preparation to the handover of the production instance.

- **Deployment** — what to verify at each promotion between environments. *Whether it belongs on this page is under consideration.*

## Establishment

### How to read it

**Docs / Action** gives the document, form or template for the step. Where the detail depends on a decision that has not been made yet — the metadata profile, the vocabularies, the identifiers — it links the requirements checklist instead.

**System specific?** marks the steps that differ by core system, and **Format** says what is handed over: a text, a table, a link, or a confirmation in Request Tracker.

**Milestones** close each phase, and are confirmed in Request Tracker — the phase is finished when that confirmation exists.
