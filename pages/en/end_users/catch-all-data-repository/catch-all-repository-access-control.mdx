# Access control and publication of the records

In the Catch-all data repository we distinguish several record states. 

**Draft** - this is the default state once you save a new record. In this state, you can edit the record - add data sets, edit keywords or attach the article. You can even delete the draft and start from scratch. Once you finish with editing you can click on the **Request record approval** button.
  
**Waiting for approval** - once you click on the **Request record approval** button you can also request DOI. In this state is the record waiting for the curator to review and approve your draft. In this state, you can only display the metadata of your record. The curator will review your record and in case there are no discrepancies your record will be approved. If the curator finds some discrepancy you will be contacted via email to correct your record and the record will be moved back to **draft** state.

**Approved** -  if your record does not contain any missing parts or denotation the curator will approve it. 

**Publicated/Public** - this is the final state of your record. In this state is assigned DOI and your record becomes publicly findable.

<Callout type="warning" emoji="⚠️">
**Public** state is final. Editing public record is not possible without a
dministrator action. At the same time is all metadata publically accessible. However the data in **Public** state can be protected by time embargo, see below.
</Callout>

## Access embargo for published records
For public records are available two elementary aproaches to the datasets for end (annonymous) users. 

1. Data (files) is available immediately after publishing the dataset by curator.

2. The record has a so-called embargo (defined period) where data/files are publicly accessible after the embargo is finished. This functionality is controlled by **Date available** setup in the draft form.

<Callout type="warning" emoji="⚠️">
The possibility of permanently locked/hidden datasets/files is currently not supported. Alternatively, you can keep your record in a draft state, where your data are not visible to anyone. The consequence is that unpublished records cannot obtain DOI and cannot be shared with anyone (e.g. journal publishers).
</Callout>

If you do not fill the field **Date available** the system automatically
use the current date when is the record published by curator.

If you choose the date in the past because the dataset was published elsewhere earlier, then this date remains in the record metadata and the data are publicly accessible when the record is published. 

If the date is set in the future (embargo) the record will be publicly accessible but the data/files will be hidden/locked. The data/files are accessible to you as author and data repository curators all the time. For other users will be the data/files visible after the embargo is finished.

<Callout type="warning" emoji="⚠️">
At this moment is not possible to set up an embargo selectively for files in the record. The embargo applies to all data attached to the record.
</Callout>

The access to the dataset is denoted via three lock icons depicted below.

### Private record
**Blue lock with avatar** => private record and files, it is visible only to the author and repository curator. This symbol accompanies the record until it is published.

![repo-access](/img/nrp/catch-all-data-repository/partialy_closed_access_persona.jpg)

### Public records can have one of the following denotation
**Green lock** => public record, public data/files, accessible to all users.

![repo-access](/img/nrp/catch-all-data-repository/open_access.jpg)

**Blue lock with clocks** => there is embargo for data/files in the record. Data will be accessible after the date defined in the record as embargo (Date available).

## Type of user roles in the Catch-all data repository
**Anonymous end-user** - can see only public records and data/files, which are not limitted with [embargo](#access-embargo-for-published-records).

**Logged user** - member of [VO_nr](catch-all-repository-introduction.mdx#register-to-access-and-create-your-very-first-record) can create a new records and can see own records and data/files (regardless to [embargo](#access-embargo-for-published-records)) and of course all public records.

**Data repository curator** - can see the records of all catch-all repository users, but only for the sake of checking the consistency of the records proposed for approval.

**Administrator** - does not involve the process of creation and approval of the records if it is not technically necessary. This role is assigned only to data repository operators.
